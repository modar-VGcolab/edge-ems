# SunSpec firmware reconciliation

Tooling and artifacts for reconciling the generated register maps against the
**as-built inverter firmware** before Gate G3 sign-off. See the task brief in
`docs/prompts/sunspec-firmware-reconciliation.md`.

## Why this exists

`maps/*.yaml` are generated by `maps/sunspec/generate.py` from the official
SunSpec model definitions, with **chosen** scale factors (`SF_VALUES`) and an
**assumed** model placement. The HIL servers and the controller read the *same*
map files, so a wrong address / type / scale is invisible in SIL/CHIL and only
breaks on the real inverter. The only way to catch it is to read the device's
*own* truth and diff.

## Tools

- `scripts/sunspec_discovery.py` — the walker library. Verifies the `SunS`
  marker, walks `(model-id, length)` headers to the `0xFFFF` end model, and
  records each model's placement, every point's offset/type, and the **actual**
  `sunssf` scale-factor values. Sources: a live device (`LiveReader`), a saved
  raw register dump (`RawDumpReader`), or our own map image (`dump_from_map`,
  a *self-dump* used only for tests).
- `scripts/diff_dump_vs_map.py` — diffs a device dump against a generated map:
  model presence/order/version, per-point offset/type, scale-factor values, and
  every canonical binding the controller uses.
- `scripts/read_real_inverter.py` — the bench CLI (`discover` and `read` modes).

## Run it against a real device

```bash
# 1. Dump the device and diff it against the candidate map in one shot
python scripts/read_real_inverter.py discover --host 192.168.1.22 \
    --map custom_bess_v1.yaml \
    --out reconciliation/bess-01.dump.json \
    --diff-json reconciliation/bess-01.diff.json

# 2. (offline) re-diff a previously captured raw register dump
python scripts/read_real_inverter.py discover \
    --from-dump reconciliation/bess-01.raw.json --map custom_bess_v1.yaml
```

A raw dump is just `{"base": 40001, "words": {"40001": 21365, ...}}` — a flat
read of the holding registers, the easy thing to capture in the field.

## Reconciling a discrepancy

The diff only *reports*. To fix a real mismatch, edit the **generator input**,
never the emitted YAML:

1. Put the device's real scale factors in `SF_VALUES` in
   `maps/sunspec/generate.py` (make them per-asset if devices differ).
2. If the device places models at a non-standard base or implements different
   optional points / lengths, extend `generate.py` to model that.
3. Regenerate: `python maps/sunspec/generate.py`.
4. Re-run: `python -m hil.parity_check` and `pytest tests hil/tests -q`.
5. Re-diff against the device until the report says `MATCH`.

Then round-trip the canonical points against the real device (encode → write →
read → decode within tolerance) and record it here.

## Artifacts in this folder

The `SAMPLE_*` files are a **synthetic** demonstration generated from our own
map image (not real firmware) so the format is reviewable and the tests have a
fixture shape to mirror. Replace them with real per-asset dumps + diff reports
when hardware is available, and commit those for traceability.

- `SAMPLE_bess-01.raw.json` — synthetic raw register dump (input).
- `SAMPLE_bess-01.dump.json` — discovery output (the device dump).
- `SAMPLE_bess-01.diff.{txt,json}` — diff vs `custom_bess_v1.yaml` (MATCH, since
  it is a self-dump; the two vendor `available_*` points are flagged for manual
  confirmation because a generic SunSpec walk stops at the end model).

> ⚠️ Because these are self-dumps, a `MATCH` here proves only internal
> consistency (parity by construction). It is **not** evidence about real
> firmware. The G3 firmware-reconciliation blocker stays OPEN until a real
> device (or a real saved dump) has been diffed and reconciled.
